Building an incident-memory engine that survives the incident

An on-call triage agent whose memory of past incidents — and of how much the human trusts its judgment — lives in CockroachDB. A lesson taught once, in one system, is instantly reusable in the next.

This is the engineering walk-through: nine small Python programs, one database, two AWS calls, and three ideas that make it more than “an agent that remembers.” Every number on this page was measured against a live CockroachDB cluster, not estimated.

The widgets below are a faithful simulator: they evaluate the real classify() rules against the real measured distances, but they run in your browser and touch no database. For the genuine article — live vector search, real Bedrock calls — open the deployed console.

00 The idea

Everyone at this hackathon will build “an agent that remembers incidents.” The interesting question is what a production on-call agent needs beyond recall. Three things, and each maps to a column in the schema:

  • A trust ledger. The agent remembers the outcome of its own judgment, per pattern. Unchanged approvals earn autonomy; a single rejection revokes it. The human-in-the-loop gate is learned, not hardcoded.
  • A memoryless counterfactual. One boolean, memory_enabled, skips the vector lookup. The same incident stream floods the queue. Flip it back and the queue melts — before/after, no infrastructure to kill.
  • Cross-system pollination. A failure_class taught from one Airflow incident matches its BigQuery and dbt cousins in embedding space. One lesson, three systems.

Why CockroachDB? An incident agent’s memory going down during an incident is the worst possible failure mode. One store holds the vectors and the trust/audit ledger — no vector-DB↔ops-DB sync, and a pattern taught from Airflow is matchable for BigQuery with no reindex lag.

The honest four-tool split

Two CockroachDB tools are load-bearing everywhere; two apply only to the CockroachDB-native incident. Stated plainly so nothing is oversold:

  • Vector Indexing + MCP Server — the core memory and the analyst interface, on every incident.
  • ccloud CLI + Agent Skills — only for the hot-range incident on the memory cluster itself, where the agent proposes CockroachDB’s own published skill to keep its own memory healthy.

03 The signature — why embeddings, not rules

Before matching, each signal becomes a normalized natural-language signature that leads with a system-agnostic symptom. For schema drift, all three systems surface the same entity (customer_region) and concept (“schema drift”, “missing / not found”) while keeping per-system detail — so their embeddings cluster, but it’s genuine similarity, not string equality.

# the same failure class, three systems — one embedding neighborhood
airflow  schema drift: expected column 'customer_region' missing … KeyError in transform
bigquery schema drift: column 'customer_region' not found - BigQuery invalidQuery, unrecognized name
dbt      schema drift: column 'customer_region' does not exist - dbt model build error

The vector is a Bedrock Titan v2 embedding (amazon.titan-embed-text-v2:0, 512 dims, normalize=true), stored in a VECTOR(512) column and matched with the cosine <=> operator. One signature() function is shared by seeding and live decisions, so patterns and signals land in the same space.

04 Decide — the engine, simulated here

The action is chosen by a deterministic rule matrix — testable, no LLM in the branch. An LLM (Bedrock Converse) only writes the human-readable reasoning. Flip the two switches and watch every decision recompute. This panel evaluates the same rules in JavaScript against the measured distances; the live console runs them in Python against the cluster. Note the two escalations that survive with memory on: a no-precedent escalation (the agent has genuinely never seen it — the teach moment) versus a precedent-cited escalation (recognized instantly, but schema/data is high-risk so a human still confirms). Same action, very different meaning.

The rule matrix

def classify(distance, risk, autonomy_granted, revoked_at, memory_on):
    if not memory_on:                         # counterfactual  → escalate
    if distance is None or distance > 0.45:   # no precedent  → escalate
    if risk == 'high':                        # rule 1       → escalate + cite precedent
    if autonomy_granted and not revoked_at:                              → auto_resolve
    else:                                                                → propose

05 Trust ledger — earn autonomy, live

This is the pattern upstream-source-connection-timeout (low-risk, seeded with 4 prior unchanged approvals). Respond the way an on-call engineer would. Autonomy is earned at 5 unchanged approvals with zero rejections, granted only by your explicit click, and revoked the instant you reject once.

4approved unchanged
0modified
0rejected
Low-risk pattern · 4/5 unchanged approvals · not yet autonomous.

Ledger writes are in-SQL and atomic (count = count + 1); CockroachDB’s serializable default makes concurrent responses safe. High-risk patterns (anything touching schema or data) can never be granted autonomy — try it in the console above: schema-drift stays escalated no matter what.

06 Teach & pollinate

When decide.py escalates something with no precedent, a human writes the root cause and resolution, and teach.py promotes it into a new pattern — embedded from the escalated signal, so its cross-system cousins then match it. Toggle schema-drift taught in the console above and watch pollinate_bq and pollinate_dbt flip from blind escalation to precedent-cited recognition, with applies_to growing [airflow] → [airflow, bigquery, dbt].

# root_cause is the human's own worked example — it feeds the reasoning call on every future match
"Upstream renamed customer_region → region_code in v3 with no deprecation.
 Every consumer hard-coding the old name breaks. Schema drift — retries won't help."

That closes the loop: one lesson, taught once from Airflow, caught in BigQuery and dbt seconds later — the whole argument for embeddings over rule matchers, running against a live vector index.

07 What only the real cluster could tell us

Everything above was verified offline before a cluster existed — deterministic self-checks, no network. That caught a lot. It did not catch these four, and three of them would have failed silently on camera.

The calibrator suggested a number that breaks the demo

A pattern matches when cosine distance ≤ a threshold. We shipped 0.30 as a placeholder and wrote a calibrator to fix it against real embeddings. It measured seeds at 0.000 and un-taught drift at 0.593, and confidently suggested 0.297.

It was measuring the wrong constraint. The distance that actually matters is taught pattern → its cross-system cousin, and pollinate_dbt sits at 0.321 — above both the suggestion and our guess. The dbt half of the pollination beat would have shown “no precedent” for an incident the agent had been taught thirty seconds earlier.

# the real safe window, measured
seed → own pattern .................. 0.000   must match
taught drift → pollinate_bq ......... 0.283   must match
taught drift → pollinate_dbt ........ 0.321   must match   ← the binding constraint
drift → nearest seed ................ 0.593   must NOT match
unrelated .......................... 0.70-0.88

window = (0.321, 0.593)  →  MATCH_MAX_DISTANCE = 0.45

A calibrator that measures half the constraints is worse than none — it produces a confident wrong number. The fix was to make it measure post-teach distances too, and warn when the current default falls outside the window.

The self-referential beat was fiction until it wasn’t

Beat 6 proposes running CockroachDB’s own analyzing-range-distribution Agent Skill. The simulated payload described a hotspot on orders_db.order_events — fine for a payload that’s only displayed, fatal for one whose SQL actually executes. It died with InvalidCatalogName.

Pointing it at agent_decisions — the agent’s own append-only decision log, whose decided_at index genuinely concentrates writes on the newest range — made the beat both work and mean what DESIGN.md claimed: the agent using CockroachDB’s published expertise to keep its own memory healthy. Simulated in its metrics, real in its subject.

Two platform facts the docs don’t lead with

  • The skill’s documented query groups by lease_holder, which needs SHOW RANGES … WITH DETAILS. CockroachDB Cloud Basic rejects it — serverless tenants get no node-level range internals (rpc error … connection reset). The tier-compatible per-index range distribution diagnoses the same hotspot.
  • CockroachDB can’t infer a placeholder’s type inside ANY() / array_append; it raises IndeterminateDatatype until you write %s::STRING. This is the line that grows applies_to — the cross-system payoff — so it failed exactly once, loudly, on first contact.

And one the design tools caught before a human would have

The console’s first palette put the brand amber and the auto-resolve green at ΔE 4.4 under protanopia — indistinguishable to a colorblind viewer. It looked fine to us. A validator script said otherwise, and the shipped trio is #E5674F / #5B93F0 / #2FA98C, which passes every check in both themes.

The pattern across all four: offline tests prove the logic you thought to write down. Real infrastructure tells you which constraints you never wrote down.

The engineering habits that actually paid

  • Verify SDK shapes against primary docs, never memory. Four of the payload formats and two API contracts differed from what a plausible guess would have produced.
  • Make the risky number measurable, then measure it. The match threshold was a guess for days. The moment it met real embeddings it turned out to be wrong in a way no test would have caught.
  • Let a reviewer read it. An automated review found a stored-XSS vector across five render paths and an overclaim in our own README — after we'd already shipped both.
  • Write the ADR when the decision reverses, not at the end. Two of the five ADRs here exist because a decision was overturned by evidence, and the reasoning would have evaporated within a day.

The through-line: every one of those came from contact with something real — a vendor's actual doc, a live cluster, a reviewer, a deployment. None came from thinking harder.
